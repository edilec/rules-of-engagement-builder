# Security boundaries

The questionnaire is untrusted data. Its fields cannot add CLI flags, file reads, executables, network adapters, signing keys, permissions or template authority. Bounded fatal UTF-8 decoding and duplicate-safe JSON precede closed-schema validation. The input set records every resolved questionnaire/font identity, including an input whose read later fails. All required text is checked in rendered form; incomplete indexes never participate in positive policy sufficiency claims.

Client/contact fields are deliberately present in the two private human drafts. Reports use fixed messages and source roles, with known-schema pointers or parent+member ordinal; they do not reproduce contact, identifier, arbitrary key, path, parser excerpt or exception stack. The candidate excludes those private fields, retains explicit boundary lists, and is unmistakably unsigned. It requires independently prepared final Scope Guard schema and client authorization. This tool cannot verify signatures or client identity.

Secret-pattern detection refuses a document rather than sanitizing away an obligation. It recognizes common private-key, token, bearer and credential-assignment shapes but cannot prove absence of all secrets or PII. Input owners must inspect their confidential data. The document model contains literal text; Markdown control syntax is escaped and PDFs contain only selectable text, font data, pages and content streams, with no active actions/forms.

Output guards inspect lstat before opening a destination; real parent confinement applies only with explicit --output-root; dev+ino comparisons cover every input/asset. Existing final files are refused. All five bounded buffers are staged in a new private directory and synced. Same-filesystem hard-link promotion refuses replacement atomically. A caught failure moves public leaves into private quarantine before inspecting their identity, avoiding a public lstat/unlink race. Only owned quarantined identities are deleted. Unexpected identities are restored by no-replace linking; a blocked restoration retains private quarantine and marks staging cleanup incomplete. Staged originals are never recursively removed while unrelated quarantine remains. The report names retained artifact roles and uses stagingCleanupIncomplete when staging removal cannot be confirmed. The success file list is produced after the five promotions, directory sync and staging cleanup.

Portable Node does not provide a directory-descriptor openat transaction. Use a trusted private output directory. Observed directory identity changes abort publication, but a hostile actor continuously replacing ancestors or a sudden process kill/power loss can leave partial drafts. The five-file set is not crash-atomic. Directory rename during a write can make earlier artifacts inaccessible under their original names; an incomplete cleanup diagnostic describes that loss of evidence, without claiming their absence at a new location.

All test assets are synthetic: documentation domains and TEST-NET IPv4/IPv6 ranges. No DNS lookup, sockets, live targets, scanners, provider calls, signatures on candidates, publication or network prerequisites are used. The denial preload observes the real product process; independent PDF tools run only in the test harness. Cooperative deadline checks bound evaluation work but cannot cancel an indefinitely stalled kernel filesystem operation. The package has no runtime or development dependencies and no install/publish lifecycle hooks.

Before later publication, require exact-tree checks, retained source/font terms, no client artifacts in tracked/tarred content, truthful commit dates, independent review and actual unsigned Scope Guard refusal. Only the integration owner updates shared catalog/website files or creates remote releases after separate human authorization. Local verification is not legal approval or live testing evidence.
